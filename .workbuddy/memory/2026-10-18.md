### 实证确认的问题（不是静态推断）

- **P0-1**：`DELETE /api/users` 时 `deleteData=false` 仍清空 `snapshots`/`user_settings`/`users` 行。根因 `user.ts:63 saveUsers()` → `syncUsersToDatabase(..., {removeMissing:true})`；`deleteData` 只控制是否 `rmSync(dataPath)`。UI 文案 `views.tsx:87` 未勾选时不显示"删除用户数据"，与行为相反。同链副作用：从 config.js 手工移除用户后，下一次任何用户变更会静默清空其数据。
- **P0-2**：`saveSnapshotWithTime(name,data,time)` 用传入的备份文件 mtime 当 `created_at`，随后立即 `pruneSnapshots`（按 created_at DESC 保留 N 条）。历史已满时导入旧备份 → 插入即被删 → 接口仍返回成功。实测：`imported-old-backup` 不在，对照组（created_at=now）在。
- **P1**：`userApi.ts` VM 沙箱一行逃逸（`console.log.constructor('return process')()` 拿到宿主 process，215 个 env）+ `Dockerfile:59 USER root`；注释 `userApi.ts:587` 声称不外泄原生能力，与事实不符。
- **P1**：`tests/cache_routes.test.ts:31 dataPath: process.cwd()` 导致 `bun test` 写真实 `data/yun-yin.db`（md5 变化，单文件可复现，`admin_sessions` 30→31）。
- **P1**：`unlink(tmp)` 只在 catch 分支，全仓无孤儿 `.tmp` 清理；`data/` 里有 10-03 留下的 0 字节 tmp。
- **P1**：`formatDuration`（`frontend/shared/src/runtime.ts:54`）阈值 `> 1000` 导致 1001~4999 秒按毫秒算，16:41 以上音频显示 `00:01`。
- **P1**：备份上传在内存中三份完整副本（readBodyBytes + Request.formData + arrayBuffer），100MB 上传在 256MiB 容器会 OOM。
- **P1**：`core/index.ts` 对 ≤32MiB 文本响应走 `Bun.gzipSync` 同步压缩，阻塞事件循环。

### 经验

- 审查此类项目时，**"接口返回成功但数据被删"要优先于"代码风格"**：两条 P0 都藏在一行 `removeMissing` / 一次 `prune` 调用里，静态读代码很容易滑过去，靠"插入后立刻查询"的实证才能锁死。
- `bun test` 前后比对 DB md5 是判断测试隔离性的最快手段。
